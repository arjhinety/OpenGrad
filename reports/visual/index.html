B0's score is a trap

The baseline reaches call_f1 0.6264 by calling a tool on 62.4% of requests whose correct answer was not a call. It recalls 97.4% of the calls that should be made, and gets 1.8% of unsupported requests right. A model that calls everything scores well on recall and badly on everything that matters.

Read with three caveats. The confirmatory partition is internal, not an untouched external benchmark — the wider upstream population has already influenced earlier work in this project, so these are pre-registered internal results. Tool-selection accuracy, argument validity and schema validity are not measured at all by this evaluator, so their absence from every row above is not a zero. The corpus changed in three ways at once — xLAM was added, ToolACE grew from 697 to 11,051 accepted records after a validator fix, and When2Call from 4,000 to 6,505 after an interrupted materialization was corrected — so no single source can be credited with the improvement. Separating them needs the ablation that the supervision configuration allows and which this experiment did not run.
